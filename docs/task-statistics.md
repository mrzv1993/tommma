# Статистика задач

Раздел открывается кнопкой «Статистика» справа от заголовка «Приоритеты» или отдельной
иконкой в боковом меню. Существующий сохраняемый порядок разделов не меняется:
новый пункт является постоянным дополнительным переходом.

## Показатели

Периоды 7, 30 и 90 календарных дней включают сегодня. Часовой пояс определяется
на устройстве и проверяется сервером. При смене периода старый ответ не может
перезаписать новый; ошибки, повторная загрузка и пустой период имеют отдельные состояния.

- Время фокуса — сумма подтверждённого `TaskWorkSession.creditedMs`. Сессия относится
  к календарному дню её начала, в том числе при переходе через полночь. Паузы и
  неподтверждённое время не начисляются. Задачи в корзине полностью исключаются из
  статистики, включая время их сессий и график фокуса. При восстановлении задачи её
  сохранённые данные снова учитываются в соответствующих периодах.
- За 7 дней график показывает дни, за 30/90 — последовательные группы до семи дней,
  с точными датами выбранной группы. Общая сумма одинакова на графике и в показателе.
- Завершённые задачи — текущие завершённые, не удалённые исполняемые задачи с датой
  завершения в периоде. Подзадачи входят, контейнеры исключены, чтобы не считать
  один результат дважды. Повторное открытие исключает задачу из завершённых;
  новое завершение учитывается один раз с новой датой.
- Жизнь при завершении определяется по сохранённому расходу бюджета: менее 15 минут —
  первая; от 15 до 45 — вторая; от 45 до 90 — третья. Сумма берётся именно на момент
  завершения, а не из изменяемого времени задачи. Зелёное сердце не используется
  в истории: оно остаётся признаком работающего таймера.
- «Нужны подзадачи» — текущее число незавершённых, не удалённых исполняемых задач,
  потративших 90 минут; от выбранного периода не зависит. Кнопка показывает список
  задач и открывает существующую форму разбиения выбранной задачи.

Старая история `actualSeconds/sessionSeconds` не имеет дат сессий и не входит в
график фокуса. Ранее завершённые задачи без даты отдельно посчитаны в примечании:
дата календарной задачи и `updatedAt` не выдаются за дату завершения.

## Данные и API

Миграция `20260907183000_task_completion_statistics` добавляет nullable
`tasks.completed_at`, `tasks.completion_focus_ms` и индекс `(user_id, completed_at)`.
Обратного заполнения нет. Старые записи и поля авторизации не меняются.
Старый код совместим с расширенной схемой; новую версию backend запускают после миграции.

Сервер устанавливает оба поля в транзакции при переходе `completed: false → true`.
Повторный PATCH `completed: true`, переименование и изменение веса их сохраняют.
Открытие задачи очищает оба значения. Клиент не может передать доверенную дату или
расход самостоятельно. Создание уже завершённой новой задачи фиксирует текущую дату и нулевой новый расход.

`GET /tasks/statistics?days=7&timeZone=Asia%2FBangkok` возвращает `{ ok, statistics }`:
период, часовой пояс, дату расчёта, время фокуса, массив по дням, число завершений,
распределение по жизням, завершённые задачи и текущие задачи для разбиения.
Допустимы только 7/30/90 и корректный часовой пояс IANA; лишние параметры отклоняются.
Все запросы ограничены авторизованным `userId`; сводка читается в одном согласованном
снимке БД. Без авторизации — 401, некорректный период — 422.

Frontend обновляет открытую статистику раз в 30 секунд, при смене периода и после
закрытия формы подзадач. Ответ старого запроса после ухода со страницы игнорируется.
Если новая версия frontend работает со старым backend, показывается понятное
сообщение о необходимости обновления; демо-значения не подставляются.

## Проверка и выпуск

`backend/test/task-statistics.test.ts` проверяет часовые пояса, границы жизней,
API и изоляцию на отдельной локальной БД через переменные `FOCUS_TEST_*`, как
существующие тесты трёх жизней. `npm run check` включает smoke нового GET-маршрута.

Production-миграция и выпуск выполняются отдельно. Миграция не удаляет данные;
при откате приложения новые nullable-поля можно оставить, чтобы сохранить историю.
