# Капитал

Раздел переносит реализованный DeFi Ledger внутрь общей сессии Tommma. Исходный код: defi `926b57c07064e84e1ee3e2d5dd2546a58e44ceb5`. Полный контракт — [specification.md](./specification.md).

## Архитектура и запуск

- Vue-раздел загружается через dynamic import; `decimal.js`, формы, Dexie и криптография попадают в его отдельный chunk. Доменные правила и Zod-контракты находятся в `backend/src/capital/shared`, используются сервером, клиентом и Worker.
- Добавочная Prisma-миграция `20260918100000_add_capital` создаёт только `capital_*` таблицы. Составные ключи и внешние связи включают `user_id`; точность сумм — NUMERIC(38,18), фиатной оценки — NUMERIC(38,8).
- PostgreSQL — источник истины. IndexedDB хранит последний успешный снимок страницы и все подтверждённые операции для сводки, отдельно для окружения/API/пользователя. При 401/403 данные очищаются; при выходе запросы отменяются. В офлайне запись отключена. Вход и подтверждение сессии требуют доступного сервера.
- Для локальной работы применить миграции к своей локальной БД, выполнить `npm run setup` при первом запуске и запускать стек через глобальный `start`. Адрес — `mdev url`; API — `mdev url api`. Для изолированного тестового стека передать `DATABASE_URL` и `VITE_DATA_SOURCE=local` команде `start`.
- Backend должен иметь исходящий HTTPS к фиксированным адресам OKX. Интеграции выполняют только GET, без торговых/платёжных методов.

## Подключения

Создать вне репозитория серверный JSON-файл с правами `0600`, передать абсолютный путь в `CAPITAL_CONNECTIONS_FILE`:

```json
{
  "123": {
    "exchange": { "apiKey": "READ_ONLY_KEY", "secret": "SECRET", "passphrase": "PASSPHRASE" },
    "wallet": { "apiKey": "ONCHAIN_KEY", "secret": "SECRET", "passphrase": "PASSPHRASE", "walletAddress": "0x0000000000000000000000000000000000000000", "chainIds": "1,42161" }
  }
}
```

`123` — проверенный ID владельца Tommma. Адрес в примере — заглушка. В production использовать ключ Exchange с правами только чтения. Не выдавать withdrawal/trade разрешения. Общие env `OKX_*` работают только при совпадении `CAPITAL_OKX_OWNER_USER_ID` с текущим пользователем. Файл подключений имеет приоритет. Секреты и полный адрес не передаются интерфейсу и не включаются в backup.

Задания запускаются внутри backend, статус хранится в БД. Одновременно допускается один запуск источника для владельца; зависшее задание становится `interrupted` после 5 минут без heartbeat. Повторный запуск безопасен: записи дедуплицируются по владельцу/источнику/external ID, курсор меняется только после успешного импорта всех полученных страниц. Курсор Wallet дополнительно привязан к адресу кошелька. После рестарта backend автоматического продолжения нет — пользователь запускает повторно.

Изменившаяся внешняя запись возвращает неархивированную операцию на проверку и сохраняет предложенные данные в аудите, не перезаписывая ручные исправления. Ошибки отдельных подключений не блокируют журнал.

## API

Внутренний префикс Fastify `/capital`; публичный через существующий proxy — `/api/capital`. Общая авторизация Tommma, `Cache-Control: no-store`. Для изменения требуется допустимый Origin либо Bearer; необязательный `X-Capital-Owner` должен совпадать с сессией.

| Маршрут | Контракт |
|---|---|
| GET `/references`, `/snapshot` | Справочники; согласованный снимок страницы, всех completed и сводки |
| GET `/operations`, `/operations/:id` | Фильтры search/type/status/source/assetId/locationId/networkId/dateFrom/dateTo, page, pageSize=20/50/100, sort=newest/oldest |
| POST `/operations`, PUT `/operations/:id` | Decimal-строки; manual create; optional allowDuplicate=true, confirmReview=true; PUT baseUpdatedAt для защиты от потерянных изменений |
| DELETE `/operations/:id` | Архивирование с аудитом; физического удаления нет |
| GET `/portfolio`, `/portfolio/operations`, `/export` | Полный портфель; completed; вся текущая выборка одним снимком |
| GET `/audit?operationId=&page=` | 100 событий на странице, только текущего владельца |
| GET `/backup`, POST `/backup/restore` | JSON v2 / атомарное добавление; совместимость с v1; лимит тела 32 MiB |
| GET `/backup/state`, POST `/backup/created` | Напоминание через 7 дней, отметка успешного экспорта |
| GET `/integrations/{okx,okx-wallet}/status` | configured, маскированный идентификатор, lastSuccessAt |
| POST `/sync/{okx,okx-wallet}` | 202, runId, alreadyRunning |
| GET `/sync/{okx,okx-wallet}/{latest,id}` | Статус, счётчик, безопасная ошибка, даты, текущий прогресс |

Повторный restore пропускает уже имеющиеся ID. Он не является откатом поверх изменённых операций. Несовместимый справочник или внешняя запись с другим ID прерывает всю транзакцию. Полное замещение для отката выполняется из резервной копии БД в отдельно согласованном эксплуатационном окне.

`.defi`: прежний формат PBKDF2/AES-GCM; пароль используется только в браузере. CSV получает весь результат фильтра, экранирует кавычки и нейтрализует spreadsheet-формулы. UI для самостоятельного редактирования справочников и отдельные экраны отчётов не входят в перенос.

## Перенос данных и переключение

1. Подтвердить владельца назначения по ID, состав данных и окно переключения. Сохранить проверенные резервные копии обеих БД и приватного файла подключений; выполнить восстановление копии в изолированную БД. Production в текущей реализации не изменялся.
2. Остановить ввод и синхронизацию в defi на время окончательного снимка. Для полного переноса использовать read-only экспорт из исходной схемы, включая архив, проводки, аудит, raw records, курсоры и запуски. Пользовательский JSON v1 не содержит всего аудита и метаданных.

```sh
# Переменные задать безопасно в окружении, не коммитить и не вставлять секреты в shell history.
node scripts/capital-export-defi.mjs --output /private/path/defi-full.json
# Экспорт использует DEFI_DATABASE_URL, REPEATABLE READ READ ONLY и создаёт файл 0600 без перезаписи.
npm --prefix backend run capital:migrate -- --input /private/path/defi-full.json --owner 123
# DATABASE_URL указывает на аккаунт назначения в тестовой БД. По умолчанию весь пробный перенос откатывается.
npm --prefix backend run capital:migrate -- --input /private/path/defi-full.json --owner 123 --apply --expected-digest DIGEST_FROM_DRY_RUN
```

3. Dry-run проверяет те же ограничения и все операции/проводки, что применяемый перенос, сверяет ID, даты, значения, статусы, ссылки и метаданные, выводит количество записей по типам/статусам, вложения, комиссии, количество и себестоимость по позициям. Любое несовпадение отменяет транзакцию. Финансовые значения в отчёте конфиденциальны — хранить его вместе с backup. `--apply` требует digest именно этого файла; повторный запуск пропускает исходные ID.
4. После отдельного согласования production повторить dry-run и apply, сравнить отчёт, проверить доступ другого пользователя, явное подтверждение импорта, JSON/.defi и повторную синхронизацию. Перенести серверные ключи только владельцу; никогда не включать их в экспорт.
5. Разрешить запись и синхронизацию только в Tommma. Оставить defi в режиме чтения на согласованный срок. Домен и выключение старого сервиса — отдельный этап.
6. При несовпадении до переключения транзакция откатывается автоматически. После переключения остановить запись и оба импорта, сохранить новый снимок, восстановить проверенную БД назначения/версию приложения либо согласовать возврат в defi с переносом новых записей. Не включать одновременно два пишущих приложения. Добавочные таблицы при откате версии не удалять.

## Проверки

```sh
npm --prefix backend run test:capital -- --maxWorkers=2
pnpm -C frontend exec vitest run --config vitest.capital.config.ts
SMOKE_USE_RUNNING_BACKEND=1 BASE_URL=http://localhost:API_PORT npm run check
```

Интеграционные тесты требуют `CAPITAL_TEST_DATABASE_URL` с локальным host и `test` в имени disposable БД; предварительно применить Prisma migrations. Без переменной интеграционные тесты явно пропускаются. CI поднимает PostgreSQL 16, применяет миграции и запускает эти проверки.

Никакие реальные финансовые операции тестами не выполняются. Проверка доступности конкретных рабочих OKX-ключей проводится отдельно владельцем после настройки; тесты запросов и фоновых заданий используют имитацию ответов провайдера.
