# Политика проверок проекта

## Фронтенд-юнит-тесты — ручной режим (16.10.2026)

По явному решению владельца frontend unit/component-тесты, composables/hooks, клиентское состояние и исключительно клиентские utilities сохранены, но не запускаются автоматически и не входят в обязательные локальные проверки, CI или деплой. Это также действует для полного gate и `workflow_dispatch` и заменяет прежние требования таких прогонов и обязательного написания фронтенд-юнит-тестов. Ручной запуск — только по отдельному явному запросу.

Типы, lint, сборка, backend/shared-domain/API-contract тесты, интеграционные и браузерные E2E-проверки остаются. Обязательные серверные/общие регрессии auth, платежей, данных, миграций и медиа сохраняются. Смешанные проверки backend/domain и клиентского контракта остаются интеграционными; расположение в `src/` или `tests/ui` не делает тест фронтендовым автоматически. Не возвращай клиентские unit-наборы в `check`, hooks, CI или deploy через вложенную/рекурсивную команду. Не заменяй тесты успешными заглушками.

В текущем main отдельный клиентский unit-набор не настроен. Не импортируй тестовые команды или исходники из незавершённых feature-веток ради этой политики.

## Выборочный CI критичных операций (23.10.2026)

Эта редакция заменяет прежние общие требования полного check/typecheck/lint/build, fallback для unknown/shared/critical и обязательного full при ручном запуске. Действует общая `/Users/mxrxzxw/.codex/validation-policy.md`.

- Локально обычные UI, тексты, оформление и некритичная логика: diff без автоматических тестов. Критичные операции: профильные server/shared-contract и интеграционные проверки из `.github/ci/checks.json`.
- `check` и `check:fast` выбирают затронутые операции; `check:plan` показывает решение; `check:full` — отдельный явный запуск всех разрешённых критичных профилей. Прежние рецепты сохранены в `.github/ci/legacy-scripts.json` (историческая справка, не автоматический fallback).
- Frontend unit/component/hooks/client-only tests остаются только по отдельному явному запросу, включая full/manual. Критичный API payload в UI требует проверки его server/shared-контракта.
- Карта — единственный источник paths/consumers/команд/входов. `dorny/paths-filter` получает сгенерированные правила. Неизвестное влияние расследуется; ошибка карты/диапазона блокирует gate, полного продуктового fallback нет.
- Сохранять весь PR/push и весь невыпущенный диапазон от подтверждённого активного frontend/backend SHA. Не использовать HEAD^ как запасную базу.
- Идентичные значимые входы используют только подтверждённое Actions evidence: repository/check/fingerprint/source/run/attempt/successful job/artifact digest. Branch evidence не становится production evidence.
- Сборка артефакта выпуска, exact-SHA/stale/lock, backup/schema/checksum, живые health/readiness/version остаются обязательными. Миграции, данные, ключи и разрешения сохраняют собственные границы.
- Новый механизм считается установленным в GitHub только после публикации и реальной проверки CI; локальная проверка не доказывает Actions reuse или production release.
